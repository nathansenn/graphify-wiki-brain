## Cognitive Pipeline

| Stage | Summary |
| Stage 1: RECEIVE | Accurately perceive what is actually being asked. Operations: literal parsing, context integration, ambiguity detection, implicit question detection. Output: precise disambiguated statement of the question. |
| Stage 2: DECOMPOSE | Break questions into atomic components. Operations: dependency analysis, parallel identification, constraint extraction, success criteria definition. Most single questions are actually bundles of sequential sub-questions. |
| Stage 3: CLASSIFY | Determine the problem type because different types require different reasoning approaches. Six types: Factual, Computational, Analytical, Synthetic, Advisory, Ambiguous. Applying the wrong approach produces wrong answers. |
| Stage 4: SCOPE | Assess the knowledge landscape before reasoning. What do I know with certainty? What with partial confidence? What don't I know? What do I need to find? Maps to four quadrants of knowledge. |
| Stage 5: RETRIEVE | Get the specific knowledge needed -- not all knowledge, not related knowledge. Retrieve the minimum knowledge necessary to enable correct reasoning. Follows a strict authority hierarchy of sources. |
| Stage 6: REASON | The core of thinking. Apply valid logical operations to move from premises (known) to conclusions (not known). Every reasoning step must use a named, valid inference rule. Five steps: state premises, identify inference, apply rule, state conclusion, check for fallacies. |
| Stage 7: VERIFY | Check reasoning against reality. Eight verification checks: internal consistency, dimensional analysis, boundary conditions, conservation laws, order of magnitude, known examples, independent method, adversarial testing. Verification is not optional. |
| Stage 8: SYNTHESIZE | Assemble verified sub-conclusions into a complete answer. Operations: integration, completeness check, coherence check, priority organization. Lead with the answer, support with reasoning, document with details. |
| Stage 9: EVALUATE | Metacognition -- thinking about thinking. Assess: does this answer the actual question? Satisfy all constraints? Meet success criteria? Five confidence levels from CERTAIN to SPECULATIVE. Identify failure modes. |
| Stage 10: COMMUNICATE | Deliver verified answer clearly. Five principles: lead with the answer, match depth to need, show work when it matters, be precise with uncertainty, say what you mean. No filler, no flattery, no performative hedging. |
| Stage 11: REFLECT | After delivering the answer, assess the process. What worked? What was difficult? Where were weak points? Serves the current conversation (flagging weaker areas) and the system overall (identifying knowledge gaps). |

# APEX Protocol Public Extract

Generated: 2026-05-26

Latest reviewed line: v2.1.6, source date 2026-05-17, package timestamp 2026-05-18.

This is not the identity protocol. It is a public operational extraction of reusable graph, verification, dispatch, and safety principles.

## Public Principles

- Use graph-indexed selective loading instead of loading every file into context.
- Map a task to the smallest relevant subsection set before acting.
- Separate creation, validation, deployment, and safety review roles.
- Prefer source-backed retrieval over assumption.
- Never fabricate retrieval results or pretend a missing source was found.
- Keep a single source of truth and reference it by stable id.
- Run numerical, logical, and evidence checks before sealing important work.
